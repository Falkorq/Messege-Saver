# Личный бот для Telegram Business аккаунтов

Бот сохраняет полученные бизнес-сообщения и присылает уведомления об их правках и удалениях. В уведомлении отдельно указаны автор сообщения и чат, где оно было изменено или удалено. Telegram не передаёт боту личность удалившего. Уведомления группируются по получателям: аккаунты из `MY_ACCOUNT_IDS` идут в один чат, аккаунты из `SECOND_ACCOUNT_IDS` (если заданы) — в другой.

В уведомлениях показываются имя отправителя, его `@username` или ID и время исходного сообщения по московскому времени (UTC+3). Подписи аккаунтов в уведомлениях задаются через `ACCOUNT_LABELS`. Если сообщение было сохранено старой версией бота, точное время может быть неизвестно.

## Доступ для друзей

Выдавать и отзывать доступ могут только аккаунты из `MY_ACCOUNT_IDS`. В личном чате с ботом:

- `/grant 123456789 Друг` — разрешить аккаунту с этим Telegram ID пользоваться ботом;
- `/access` — показать приглашённые аккаунты;
- `/revoke 123456789` — отозвать доступ.

Друг сначала отправляет боту `/start` и передаёт показанный ID владельцу. После `/grant` он может пользоваться командами и, если нужны уведомления о правках и удалениях, подключить бота в Telegram Chat Automation. Уведомления друга отправляются в его личный чат с ботом. Его watchlist, настройки и статистика отделены от других пользователей. При отзыве доступа команды и проверки профилей прекращаются, ожидающие уведомления не отправляются. Уже сохранённые сообщения в базе автоматически не удаляются.

Доступ сохраняется в `messages.sqlite3` и действует после перезапуска. Аккаунты, заданные в `.env`, через `/revoke` отключить нельзя. Владелец сервера по-прежнему имеет технический доступ к базе с сообщениями разрешённых Business-чатов.

## Настройка

1. Создайте бота через BotFather и скопируйте токен.
2. На каждом подключаемом аккаунте откройте личный чат с ботом и отправьте `/start`. Бот ответит Telegram ID аккаунта. Запишите все ID.
3. Скопируйте `.env.example` в `.env`. Укажите токен и ID своих аккаунтов в `MY_ACCOUNT_IDS` (через запятую). `MY_CHAT_ID` — ID чата, куда отправлять уведомления с этих аккаунтов. При необходимости задайте второго получателя: `SECOND_CHAT_ID` и `SECOND_ACCOUNT_IDS` — его чат и его аккаунты. Владельцы обоих чатов должны отправить боту `/start`. Необязательный `ACCOUNT_LABELS` задаёт подписи аккаунтов в уведомлениях: `111111111:Home,222222222:Work`.
4. Подключите бота в настройках Telegram Business каждого аккаунта и дайте ему доступ к нужным чатам и сообщениям.
5. Установите Python 3.10+ и зависимости: `python -m pip install -r requirements.txt`.
6. Запустите: `python bot.py`.

## Мониторинг профилей

Для чтения `bio` и актуальной аватарки используется отдельная MTProto-сессия пользователя: обычный Bot API эти данные для произвольных пользователей не предоставляет. Модуль изолирован в каталоге `profile_monitor`, а сообщения Business Bot продолжают обрабатываться прежним кодом.

1. Создайте Telegram API-приложение на `my.telegram.org` и добавьте `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`.
2. На доверенном компьютере выполните `python create_telegram_session.py`, войдите в нужный Telegram-аккаунт и скопируйте выведенное значение `TELEGRAM_SESSION` в `.env`. Эта строка даёт доступ к аккаунту, поэтому не публикуйте её.
3. `PROFILE_DATA_DIR` задаёт каталог локальных копий изменившихся аватарок. По умолчанию это `profile_data`.
4. Перезапустите приложение и откройте интерфейс командой `/menu`.

Аккаунты одного получателя используют общий watchlist и его настройки. У второго получателя (если задан) — отдельный watchlist. Добавление по числовому ID возможно, если MTProto-аккаунт уже знает этого пользователя; публичный `@username` разрешается напрямую.

Для проверок после перезапуска модуль сохраняет `access_hash` пользователя в той же базе. Схема существующей `messages.sqlite3` обновляется автоматически. У старых записей `access_hash` будет восстановлен через сохранённый `@username` при следующей проверке. Если username уже сменился и профиль не находится, выполните `/watch @текущий_username`: запись получит `access_hash`, при этом прежний snapshot и история сохранятся. Для пользователя без username откройте диалог с ним в аккаунте `TELEGRAM_SESSION`, затем выполните `/watch user_id`. Один только числовой ID незнакомого MTProto-аккаунту пользователя Telegram разрешить не может.

Проверки выполняет один scheduler. Интервал, уведомления, хранение аватарок и формат уведомлений меняются в inline-интерфейсе. Snapshot и время последней проверки сохраняются в `messages.sqlite3`, поэтому перезапуск не создаёт ложные события и не сбрасывает расписание.

## Запуск на сервере

Используйте сервер или хостинг с Python 3.10+, доступом к Telegram и постоянным хранилищем. Скопируйте проект в отдельный каталог или клонируйте репозиторий. Создайте виртуальное окружение, установите зависимости из `requirements.txt` и заполните `.env` по примеру `.env.example`.

Запускайте приложение из корня проекта:

```sh
python app.py
```

Для постоянной работы настройте менеджер процессов или службу своего хостинга: рабочий каталог — корень проекта, команда запуска — Python из виртуального окружения и `app.py`. Включите автоматический перезапуск при сбое. Не запускайте несколько копий бота с одним токеном одновременно.

Храните SQLite-базу и каталог аватарок на постоянном диске, который сохраняется при перезапуске и обновлении приложения. Пути задаются через `DB_PATH` и `PROFILE_DATA_DIR`. Скрипт `create_telegram_session.py` нужен только для первоначального создания сессии. Баннер можно заменить своим файлом и указать его путь в `UI_BANNER_PATH`; по умолчанию используется `banner.jpg`.

Файл `messages.sqlite3` создаётся автоматически. Храните его и `.env` в закрытом месте: в базе есть тексты личных сообщений. `RETENTION_DAYS` задаёт срок хранения сообщений; по умолчанию 90 дней.

## Команды

С любого подключённого аккаунта в личном чате с ботом:

- `/status` — состояние своих подключений, фильтра, очереди уведомлений и размер базы;
- `/retry_failed` — повторно отправить уведомления, которые Telegram отклонил постоянной ошибкой, после устранения её причины;
- `/only_others on` — не сохранять новые сообщения, отправленные самим владельцем аккаунта, и не уведомлять об их правках и удалениях;
- `/only_others off` — снова учитывать все сообщения (режим по умолчанию).
- `/style` — показать примеры оформления;
- `/setemoji delete` и `/setemoji edit` — выбрать премиум-эмодзи для заголовков удалений и правок. Добавьте эмодзи в сообщение с командой или ответьте командой на сообщение с нужным эмодзи.
- `/menu` — открыть inline-интерфейс Personal Bot;
- `/watch @username` или `/watch user_id` — сохранить baseline и начать наблюдение;
- `/unwatch @username` — отключить наблюдение;
- `/watchlist` — показать список;
- `/profile_history [@username]` — последние изменения профиля;
- `/username_history [@username]` — история username.
- `/mute @username 30m` — удалять новые входящие сообщения пользователя в течение указанного срока;
- `/mute user_id навсегда` — бессрочный мут;
- `/unmute @username` — снять мут;
- `/mutelist` — активные муты;
- `/chatstats` — общая сводка и самые активные чаты;
- `/chatstats @username` — накопительная статистика Business-чата. Если один собеседник есть у нескольких ваших аккаунтов, бот покажет команды с нужным ID аккаунта. В inline-интерфейсе список можно сортировать по недавней активности или числу сообщений, а карточка разделена на обзор, медиа и слова. Старые агрегаты относятся ко всему времени наблюдения, точного фильтра по дням для них нет.

В самом Business-чате владелец аккаунта может отправить `!mute 30m`, `!unmute`, `!mutestatus` или `!stats`. Результат приходит в личный чат управления ботом. Бот пытается удалить служебную команду из Business-чата; если Telegram запрещает удаление, команда всё равно выполняется, а в ответе появляется предупреждение. Для удаления нужны соответствующие права Business Bot и доступ к этому чату. Без них `!mute` не сможет удалять новые сообщения.

Статистика учитывает сообщения, которые Business Bot фактически получил. При первом запуске модуль добавляет уже сохранённые сообщения из `messages.sqlite3`, затем считает новые сообщения без дублей. Удаление сообщения не вычитает его из накопительной активности.

Для BotFather (`/setcommands`) можно использовать:

```text
start - Показать мой Telegram ID
menu - Открыть Personal Bot
watch - Добавить профиль в наблюдение
unwatch - Отключить наблюдение
watchlist - Список наблюдения
profile_history - История профиля
username_history - История username
mute - Включить мут пользователя
unmute - Снять мут пользователя
mutelist - Активные муты
chatstats - Статистика Business-чата
status - Состояние подключений и очереди
retry_failed - Повторить неотправленные уведомления
only_others - Учитывать только чужие сообщения
style - Показать оформление
setemoji - Настроить эмодзи
grant - Выдать другу доступ по Telegram ID
revoke - Отозвать доступ друга
access - Список приглашённых аккаунтов
```

Настройка фильтра общая для аккаунтов одного получателя и отдельная между получателями. Команды управления от других Telegram ID игнорируются. При переключении уже сформированные уведомления остаются в очереди.

Эмодзи сохраняются в SQLite и задаются отдельно для двух получателей уведомлений. По умолчанию используются выбранные кастомные значки 🗑 для удаления и ✏️ для правки, а также отдельные значки «Было» и «Стало». Telegram разрешает боту отправлять кастомные эмодзи в личные чаты, если владелец бота имеет Telegram Premium; при отказе Telegram бот отправит обычное оформление.

Бот может сообщить только о сообщениях, которые получил сам. Удаление старого сообщения, отсутствующего в базе, восстановить нельзя. Контакты, геопозиции, места, опросы и dice сохраняются как текстовое описание. Для неизвестных типов сохраняется их название; недоступное боту содержимое восстановить нельзя.

Временные ошибки отправки повторяются с задержкой. Постоянные ошибки видны в `/status` как «Требуют внимания»; после исправления причины используйте `/retry_failed`. Очередь помнит уже отправленные медиа и части длинного текста, чтобы при обычном повторе их не дублировать. При аварии между ответом Telegram и записью результата в SQLite повтор всё ещё возможен.

При смене `MY_CHAT_ID` или `SECOND_CHAT_ID` перезапустите бота: он перенаправит ожидающие уведомления по текущей настройке. После изменения получателя команды фильтра и оформление для нового чата настраиваются заново.
